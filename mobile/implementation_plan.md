# AI-Powered Smart Suggestion Recommendation Engine

This plan details a state-of-the-art **Smart Suggestion Engine** for the "More Like This" panels and related recommendation feeds. It leverages **Mistral AI** to discover deep visual, artistic, and conceptual relationships between images, synthesizing image metadata (Title, Description, Location) and real-time user interactions (Likes, Uploads, and Clicks) to yield highly personalized grids.

---

## Technical Architecture

### 1. SQLite Schema Integration
We will store and track the following in the database:
* `ai_concepts` column in `images` table: A JSON array of 5–6 rich, conceptual keywords generated by Mistral AI.
* `views` table: Tracks user click interactions to build a real-time interest profile.
  ```sql
  CREATE TABLE IF NOT EXISTS views (
    userUid TEXT NOT NULL,
    imageId TEXT NOT NULL,
    viewedAt TEXT NOT NULL,
    PRIMARY KEY (userUid, imageId),
    FOREIGN KEY (imageId) REFERENCES images(id) ON DELETE CASCADE
  );
  ```

### 2. Multi-Metadata AI Synthesis (Title, Description, Location)
When Mistral AI analyzes an image (either upon first view for past uploads, or during initial upload):
* The API payload includes the **Image URL** alongside the user-provided **Title, Description, and Location** (e.g., `"Kyoto, Japan"`).
* Mistral synthesizes both the visual cues (color tone, subject matter, style) and the context cues (place names, historical relevance, user intents) to produce highly holistic concepts (e.g., `["zen temple", "traditional japanese architecture", "kyoto autumn", "golden reflection"]`).

### 3. Real-Time Interaction Tracking (Clicks, Likes, Uploads)
* **Frontend View Trigger**: Every time a logged-in user clicks to open an image detail modal, the frontend sends a background request:
  ```javascript
  fetch('/api/images?action=view', {
    method: 'POST',
    body: JSON.stringify({ imageId, userUid })
  });
  ```
* **Real-time User Interest Vector**: When computing recommendations, the backend extracts the `ai_concepts` from:
  1. Images the user **uploaded** (weight = 1.5).
  2. Images the user **liked** (weight = 1.0).
  3. Images the user **clicked/viewed** (weight = 0.5).
* These are aggregated and normalized into the user's **Dynamic Taste Profile** in real-time, updating immediately as they browse the gallery.

### 4. Hybrid Personalized Recommendation Scoring
For a target `imageId` and active `userUid`, candidate images are ranked using:
$$\text{Score} = (4 \times \text{AI Concept Overlap}) + (3 \times \text{Metadata Match}) + (2 \times \text{Taste Profile Alignment}) + (0.1 \times \text{Popularity})$$

Where:
* **Metadata Match**: Direct text search alignment between the target image's Title/Description/Location and the candidate image's fields.
* **Taste Profile Alignment**: Matches the user's real-time aggregated Taste Profile (built from Uploads, Likes, and Clicks).
